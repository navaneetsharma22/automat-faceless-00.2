## Shot 13 readback mismatch and diagnostic contradiction investigation â€” 31 October 2026

Investigated the contradiction where Shot 13 blocked with `editor_exact_readback_mismatch`, while persisted `pre_activation_inspection` diagnostics showed identical expected/actual lengths (3,920 code units / bytes) and identical SHA-256 hashes, with the UI displaying â€œNot dispatched. Provider outcome not started.â€

Trace of four target areas:

1. `flowTimedGenerateRuntime` exact comparison:
   - Evaluated `actual === expectedText` in-page, but discarded `actualText` rather than returning it.
   - When candidate buttons were disabled or missing (`candidates.length !== 1 || enabled.length !== 1`), it created a dummy marker node `<span>` with `dataset.afState`, omitting `dataset.afExact`.
2. Writing and reading `button.dataset.afExact`:
   - Writing comparison results to DOM attributes mutated host page DOM elements.
   - When button readiness failed, `marker.dataset.afExact` was absent/undefined, evaluating to `false` when read.
3. `Runtime.evaluate` / `Runtime.callFunctionOn` result parsing:
   - Evaluated wrapper object via CDP `Runtime.evaluate` (`returnByValue: false`) and parsed `this.dataset.afExact === 'true'`.
   - In `generationQueue.ts`, `if (!inspection.exactPrompt)` was prioritized before checking `inspection.generate !== "identified"`. A disabled or unready button was erroneously classified as `editor_exact_readback_mismatch`.
   - The remote button handle was passed to `inspectFlowImageButton`, which previously only checked `!this.isConnected`, failing to verify ownership or connection to the active composer boundary.
4. The later diagnostic text read:
   - Because Sample 1's actual text was discarded, `generationQueue.ts` performed a separate second CDP call `readCurrentFlowEditorText` (Sample 2).
   - In Sample 2, the text in the editor was settled (or had been matching all along while Generate was disabled).
   - `generationQueue.ts` stamped Sample 2's matching 3,920 code units and identical SHA-256 into the diagnostic, creating the observed contradiction.

Evaluated hypotheses:

- **Different DOM samples**: CONFIRMED. Sample 1 failed or was misclassified, but Sample 2 was read later for diagnostics and stamped over Sample 1.
- **Replaced button**: CONFIRMED RISK. Between CDP round trips, button identity was not revalidated against the active composer boundary; now guarded by `revalidateAndInspectButtonRuntime`.
- **Stale metadata / Incorrect CDP parsing**: CONFIRMED. Missing `dataset.afExact` on dummy marker spans was parsed as `exactPrompt: false`, misclassifying button disabled state as a text mismatch.

Demonstrated fix:

- Capture comparison outcome and bounded text diagnostics from the **SAME editor sample** (Sample 1).
- Discontinue DOM attribute mutation (`dataset.afExact`). Return pure data `{ composer, exactPrompt, actualText, readError, generate, button }`.
- Preserve remote button handle (`buttonObjectId`) separately and cleanly release the evaluation wrapper object.
- Revalidate editor and button ownership via `revalidateAndInspectButtonRuntime`: verifies the button is connected, visible, enabled, located inside `boundary.contains(button)` enclosing the active editor, and is the unique enabled candidate.
- When Sample 1 mismatches but a later settled Sample 2 matches, report the samples separately (`settledActualCodeUnits`, `settledActualSha256`, `settledEqual: true`) without bypassing exact equality.
- Preserve Shots 10â€“12 receipts, 40-second scheduler interval, and Shot 13 failure evidence. Zero live provider actions.

## Bounded pre-activation readiness waiting and Shot 14 guarded recovery â€” 31 October 2026

Investigated premature blocking on transient Generate button unreadiness (live Shots 10â€“13 Sent, Shot 14 blocked with `generate_disabled` while matching prompt text 3,954 code units remained intact in the editor). Requiring manual retry for ordinary temporary unreadiness defeated timed queue operation.

Implemented bounded pre-activation readiness waiting:

1. **Minimum Interval Preservation**: Preserved 40,000 ms as the minimum interval after the previous dispatch receipt before examining readiness.
2. **Visible Waiting State**: When the verified Generate button is disabled during pre-activation inspection, the queue enters a visible `Waiting for Flow readiness` state instead of immediately blocking.
3. **Persisted Readiness Deadline**: Bounded 60-second maximum additional wait (`FLOW_READINESS_WAIT_TIMEOUT_MS = 60_000`) persisted in Dexie on `dispatchIntent.readinessDeadlineAt`. Read-only rechecks use exponential backoff (500 ms up to 2,000 ms).
4. **Zero Mutation While Waiting**: No text reinsertion, prompt rewriting, or clicks are sent while waiting.
5. **Fresh Revalidation Before Activation**: When enabled, the dispatcher freshly revalidates exact source text equality, project/document bindings, unique button ownership via `revalidateAndInspectButtonRuntime` (`boundary.contains(button)` and unique enabled candidate), queue revision, and Pause/Stop state before authorizing activation. Changed text, bindings, or button ownership safely refuse (block).
6. **Timeout and Pause/Stop**: If the button remains disabled after 60 seconds, the queue pauses with `flow_generate_readiness_timeout` and reverts the item to `pending` with `providerOutcome: "not_started"`. Pause/Stop during waiting prevents activation authorization.
7. **Worker Restart Reconcilation**: Unactivated items with expired deadlines pause with `flow_generate_readiness_timeout`; unexpired items safely revert to `pending` and reschedule without early or duplicate dispatch.
8. **Shot 14 Guarded Recovery**: Existing blocked Shot 14 is not automatically unblocked during upgrade. The user runs read-only inspection, verifies prompt equality (3,954 code units), and triggers guarded retry ("Retry Shot 14 (guarded)"), which unblocks Shot 14 to `pending` and pauses the queue (`guarded_retry_ready`) for safe resumption.
9. **Duplicate Wakeup Protection**: Concurrently triggered alarms execute sequentially via the serialized queue lock without duplicate dispatch.
