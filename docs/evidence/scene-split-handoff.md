# Part 4 — local split handoff evidence

## Implemented boundary

The Vids Downloads panel exposes **Split downloaded video** only for a completed combined-download attempt with its exact Chrome download ID. The handoff shows the document ID, attempt ID, Chrome download ID, and Chrome-reported source path. The extension exports a JSON boundary manifest bound to that record. The manifest stores only the selected source basename, not the local path.

In measured-boundary mode, the user enters every scene name, zero-based start-frame index, exclusive end-frame index, and corresponding source-frame timestamps. The manifest records that the entries follow the actual edited Vids timeline and that frame timestamps were read from the source MP4; these are user attestations. This mode has no default scenes, cuts, scene counts, prompt-derived boundaries, or inferred ordering. The companion checks frame/timestamp alignment against the selected MP4 before encoding.

The existing Windows companion remains user-launched through `Run-Local-Vids-Split.cmd`. The extension does not run FFmpeg, invoke the companion, or communicate with it. The user selects the completed combined MP4, exported manifest, and a parent output folder in the companion; the companion creates a unique `VidsSplit-*` directory. Chrome's configured Downloads location and the user-selected splitter output location are separate. The combined source is retained; existing output files are refused. Per-scene frame count, duration, and audio are verified by the legacy CLI/ffprobe path, and the Windows launcher writes its separate verification summary.

## Manual acceptance checklist

1. Open the intended Vids document and confirm the manually prepared timeline and saved state.
2. Download the whole MP4 through the existing Vids flow; confirm the completion state, exact document ID, attempt ID, and Chrome download ID.
3. Play the combined MP4 and inspect its media properties. Chrome completion alone does not verify playback or media properties.
4. Choose either measured boundaries from the edited timeline/source timestamps, or **Split by duration** and enter seconds per clip plus expected count. Both exports are attached to the exact completed download record.
5. Launch `Run-Local-Vids-Split.cmd` yourself and select the same combined source and exported file. For duration mode, review every probed frame range and any remainder/count difference, explicitly confirm the proposal, then choose a separate parent output folder.
6. Inspect `verification-results.json`, each output's frame count, duration, cadence and audio, and playback/scene separation. Confirm the combined source remains unchanged and the scene files are correctly separated.

## Fixed-duration mode — 6 November 2026

Vids Step 4 now offers a separate **Split by duration** mode. It exports settings bound to the completed document, attempt, and Chrome download ID, with the entered seconds per clip and expected clip count. The settings contain no frame indices/timestamps and carry no manual-measurement or user-attested boundary provenance. The measured-boundary form remains available unchanged.

The user-launched Windows companion identifies fixed settings, probes the selected local MP4 with ffprobe, and previews the decoded video duration, frame count, resolution, timestamp-derived average frame rate, exact Vids/download binding, and sequential frame ranges. Ranges are generated by cumulative duration targets snapped to actual source frame timestamps. Every source frame, including any short remainder or footage beyond expected duration, remains in the proposed ranges. The companion requires confirmation for every plan and an explicit acknowledgement for short remainder, extra footage, source-filename mismatch, or expected-count mismatch; cancel creates no outputs. It then writes the generated ranges into the new output folder and invokes the existing re-encoding splitter. The original MP4 remains in place and output collision checks remain active.

The splitter preserves source dimensions and source frame timestamp cadence with re-encoding and passthrough frame timing; output resolution, frame count, frame cadence, duration, and audio are verified. No keyframe-only stream-copy path or assumed 24 fps is used. Scene changes are not detected. Fixed-duration mode assumes the edited Vids timeline uses the entered duration.
